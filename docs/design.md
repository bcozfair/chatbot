# กฎหน้าตาของแอปนี้

**ไฟล์นี้คือกฎของ "สิ่งที่มีอยู่แล้ว" ไม่ใช่ข้อเสนอให้สร้างดีไซน์ซิสเทมใหม่** ทุกบรรทัดข้างล่าง
อธิบายของที่อยู่ในทรีนี้วันนี้ พร้อมเหตุผลว่าทำไมถึงเป็นแบบนั้น ตัวเลขทั้งหมดวัดเมื่อ **2026-09-12**
เว้นที่ระบุวันอื่น

**การรื้อทำใหม่คือความผิดพลาดที่ไฟล์นี้มีไว้กัน** ข้อเสนอที่ขึ้นต้นว่า "ตั้งชุดโทเคนใหม่ให้สะอาดกว่านี้"
หรือ "ย้าย LIFF ไป React" หรือ "ทำ component library ให้ admin ใหม่ทั้งชุด" — ถ้าของที่มีอยู่ทำงาน
ไม่ได้กับสิ่งที่กำลังจะทำ นั่นคือคำถามที่ต้องกลับไปถามเจ้าของ (`AGENTS.md` ข้อ 7) ไม่ใช่ใบอนุญาต
ให้สร้างระบบคู่ขนาน

## 0. ลำดับก่อนแตะโค้ด

ห้าขั้น และขั้นที่ 4 คือขั้นเดียวที่ข้ามไม่ได้:

1. **ตอบให้ได้ก่อนว่าจอนี้อยู่พื้นผิวไหน** (หัวข้อ 1) — กติกาของสี่พื้นผิวไม่เหมือนกันเลย
2. **เปิดจอที่ใกล้เคียงที่สุดที่มีอยู่แล้วดูจริง** ไม่ใช่เดาว่ามันหน้าตาอย่างไร
3. **เขียนคำถามที่ยังไม่รู้ออกมาเป็นคำถาม** (เช็กลิสต์หัวข้อ 10 ใช้ย้อนกลับเป็นรายการคำถามได้ตรง ๆ)
4. **ส่ง mockup ที่ render แล้ว รอคำยืนยันจากเจ้าของ** — เงียบไม่ใช่โอเค ตอบเรื่องใกล้เคียงไม่ใช่โอเค
5. เขียนโค้ด แล้วเดินเช็กลิสต์หัวข้อ 10 ก่อนบอกว่าเสร็จ

ถ้ารอบนั้นทำให้ประโยคในไฟล์นี้ไม่จริงอีกต่อไป **ให้แก้ไฟล์นี้ในคอมมิตเดียวกัน**

## 1. สี่พื้นผิว กติกาคนละชุด

นี่คือรากของบั๊กดีไซน์ที่เกิดซ้ำที่สุดในโปรเจคนี้ — เอากติกาของพื้นผิวหนึ่งไปใช้กับอีกพื้นผิว

| พื้นผิว | ใครดู | เทคโนโลยี | ความกว้างจริง | ไอคอน | ธีม |
| --- | --- | --- | --- | --- | --- |
| **Admin Portal** `frontend/` | แอดมิน/หัวหน้า บนจอทำงาน | React 19 + Tailwind 4 | 1280–1920 · หุบได้ถึงมือถือ | `lucide-react` (29 ไฟล์) | **มืดเป็นค่าเริ่มต้น** + สลับสว่างได้ |
| **LIFF** `liff_pages/` | เซลล์ ในแอป LINE บนมือถือ | HTML + Vanilla JS ล้วน | ~390 เป็นหลัก | อีโมจิ | สว่างอย่างเดียว |
| **LINE Flex** `utils/flexTemplates.ts` | เซลล์ ในห้องแชท | JSON schema ของ LINE | LINE เป็นคนกำหนด | อีโมจิ | LINE เป็นคนกำหนด |
| **PDF** `pdfGenerator.ts` | ลูกค้า บนกระดาษ/หน้าจอ | HTML → Chromium → A4 | A4 ตายตัว | ไม่มี | ขาวอย่างเดียว |

**ผลที่ตามมาซึ่งต้องรู้ก่อนแก้อะไร**

- **สีแบรนด์มีสองสะกด และทั้งคู่ถูกในบริบทของตัวเอง** — Admin ใช้ `#009032` (ตัวแปร `--brand`)
  ส่วน LIFF ใช้ `#1e8f1e` (`--green`) สองค่านี้เกิดคนละรอบและ **ไม่เคยอยู่บนจอเดียวกัน**
  จะรวมเมื่อไหร่เป็นการตัดสินใจของเจ้าของ ไม่ใช่การเก็บกวาดระหว่างทาง
- **Flex ไม่ได้ใช้สีแบรนด์เลย** — `flexTemplates.ts` ใช้ `#2563EB` (11 จุด) `#1F2937` (13)
  `#4B5563` (14) คือชุดน้ำเงิน-เทามาตรฐาน เพราะ Flex ไม่มีตัวแปร CSS ให้ใช้ ทุกสีต้องเป็น hex
  ตรง ๆ ในไฟล์ — **นี่เป็นข้อจำกัดของ LINE ไม่ใช่ความมักง่าย** ห้ามไปไล่แทนด้วย `var()`
- **อีโมจิเป็นไอคอนที่ถูกต้องบน LIFF/Flex/ข้อความ LINE** (วัดได้: LIFF 150 ตัว · Flex 76 ·
  `lineHandler.ts` 110) เพราะ LINE เรนเดอร์ SVG ของเราไม่ได้ **แต่บน Admin ห้าม** — ที่นั่นมี
  `lucide-react` แล้ว (อีโมจิใน `frontend/src` เหลือ 16 จุด ซึ่ง **10 จุดเป็น `⚠️` ในคอมเมนต์
  ของไฟล์** — ตัวนั้นไม่ใช่ปัญหา — และ **6 จุดอยู่บนจอจริง**: `👋` ในคำทักทาย, `©` ในฟุตเตอร์
  หน้าล็อกอิน, `⚠` ในคำเตือน pool ไม่พอ, `❌` ในตัวอย่างข้อความ Flex ที่หน้า `BlockRules`
  ยกมาโชว์ และ `⚠️ ยังไม่ได้บันทึก` อีก 2 จุด — ตัวเลข 6 นี้ลดลงได้เท่านั้น ห้ามเพิ่ม)

## 2. Admin — สีอยู่ที่ `index.css` ที่เดียว

**สีดิบใน `.tsx` / `.ts` = 0 จุด (วัดแล้ว) และนี่คือตัวเลขที่ต้องคงไว้ที่ 0**

`frontend/src/index.css` ทำงานสองชั้น และการแยกสองชั้นคือประเด็นทั้งหมด:

1. `:root` ประกาศ **จานสีจริง** เป็น `--c-*` (พื้นผิว 4 ระดับ · หมึก 6 ระดับ) + `--brand-*`
2. `@theme` เอาจานนั้นไป **ทับ token ของ Tailwind** (`--color-slate-*`, `--color-red-*`, …)

ผลคือคอมโพเนนต์ยังเขียน `bg-card` / `text-slate-900` / `border-slate-200` ตามปกติ แล้วได้สีมืด
อัตโนมัติทุกหน้า **ไม่ต้องแก้ทีละไฟล์** — และนั่นคือเหตุผลที่ห้ามพิมพ์ hex ลง `.tsx`: hex ที่พิมพ์มือ
จะเป็นจุดเดียวที่ไม่สลับตามธีม แล้วมันจะไม่พังตอนที่พิมพ์ แต่พังตอนที่มีคนกดปุ่มสลับธีม

**บันไดกลับด้านในธีมมืด** — `slate-50` = มืดสุด, `slate-900` = สว่างสุด ส่วน `50–300` ของสีสถานะ
คือ **พื้น/ขอบ** และ `400–800` คือ **ตัวอักษร/ไอคอน** ถ้าเขียนกลับกันจะได้ตัวอักษรที่อ่านไม่ออกบน
ธีมหนึ่งและอ่านออกบนอีกธีมหนึ่ง ซึ่งเป็นบั๊กที่คนเขียนไม่มีทางเห็นเพราะเปิดอยู่ธีมเดียว

**ธีมมืดเป็นค่าเริ่มต้น** (`ThemeToggle.tsx` + `localStorage['admin-theme']`) และตัวเซ็ตธีมตอนโหลด
อยู่ใน `<head>` ของ `admin.html` / `index.html` **โดยตั้งใจ** เพื่อไม่ให้จอวาบขาวก่อน React ทำงาน —
ย้ายไปไว้ใน React เมื่อไหร่ อาการวาบขาวกลับมาทันทีโดยไม่มี error
`:root { color-scheme: dark }` ก็เป็นของจำเป็น ไม่ใช่ของประดับ: มันทำให้ date picker, dropdown
และ autofill ของ native มืดตาม

**เบรกพอยต์เป็นค่าดีฟอลต์ของ Tailwind** (`sm 640 · md 768 · lg 1024 · xl 1280`) — ไม่มี
`--breakpoint-*` ใน `@theme` **อย่าเพิ่ม** การใช้งานจริงกระจุกที่ `sm:` (63 จุด) แล้วค่อย `lg:` (19)
`xl:` (10) `md:` (5) แปลว่าแอปนี้คิดเป็น "มือถือ ↔ จอทำงาน" สองขั้นเป็นหลัก จอที่เขียนใหม่ควรอยู่ใน
บันไดเดิม ไม่ใช่หยิบเส้นที่ยังไม่มีใครใช้

## 3. Admin — อะไรที่ใช้ซ้ำได้แล้ว และอะไรที่ยังไม่ใช่

| ของ | ไฟล์ | สถานะจริงวันนี้ |
| --- | --- | --- |
| `PageHeader` / `PageHeaderOutlet` | `admin/PageHeader.tsx` | **16 หน้า import จริง** — ตัวอย่างของร่วมที่ใช้ได้ผล |
| `ThemeToggle` | `admin/ThemeToggle.tsx` | ใช้ร่วมได้ วางตรงไหนก็ได้ |
| `SettingToggle` · `DateInput` · `ProductComboBox` · `ScopeComboBox` | `admin/*.tsx` | ใช้ร่วมได้ |
| ชุดคอมโพเนนต์ตาราง/ตัวกรอง (`TableCard` `SortHeader` `Pagination` `EmptyState` `SkeletonRows` `StatusPill` `FilterCard` …) | `admin/logs/ui.tsx` | **มีอยู่จริงและดีมาก แต่ใช้แค่ 5 หน้า** (4 หน้าในกลุ่มบันทึก + `ApiLogs`) |
| ตัวช่วยแสดงผล (`formatDateTime` `relativeTime` `errMsg`) | `admin/logs/format.ts` | เดิมเป็นสำเนาจาก `ApiLogs.tsx` แล้วยุบกลับมาที่เดียว |

**ของจริงที่ต้องรู้: มี 15 ไฟล์ที่เขียน `<table>` ของตัวเอง** ทั้งที่ `TableCard` + `SortHeader` +
`Pagination` มีอยู่แล้วใน `logs/ui.tsx` และ **`⚠️ ยังไม่ได้บันทึก` ถูกพิมพ์ซ้ำคำต่อคำใน 2 ไฟล์**
(`CreditPolicy.tsx:198` และ `ShippingFee.tsx:283`) — นั่นคือ SaveBar ที่ยังไม่ได้เกิด

**กติกาจากข้อเท็จจริงนี้** — ไม่ใช่ "ไปรื้อ 15 ไฟล์ให้ใช้ของร่วม" (นั่นคือการรื้อที่หัวไฟล์นี้ห้ามไว้)
แต่คือ:

- **หน้าใหม่ใช้ของใน `logs/ui.tsx` ก่อนเสมอ** ถ้ามันไม่พอ ให้เพิ่ม prop ที่นั่น ไม่ใช่ก๊อปไปแก้
- **ชื่อไฟล์ `logs/ui.tsx` เป็นร่องรอยของประวัติ ไม่ใช่ขอบเขตการใช้งาน** — มันเริ่มจากกลุ่มบันทึก
  แล้วกลายเป็นชุดคอมโพเนนต์ที่สมบูรณ์ที่สุดของแอป การย้ายมันขึ้นไปหนึ่งชั้นเป็นงานที่ทำได้
  แต่ต้องเป็นงานของตัวเอง ไม่ใช่ผลข้างเคียงของงานอื่น
- **สำเนาไม่เคยพังตอนที่ก๊อป มันพังตอนที่ตัวจริงถูกปรับปรุงแล้วสำเนาไม่ได้ตามไป** —
  `logs/format.ts` มีคอมเมนต์บันทึกไว้เองว่ามันเคยเป็นสำเนาแล้วถูกยุบกลับ

## 4. คำบนจอ — เรียกให้ตรงกันทั้งแอป

**ตั้งชื่อใหม่ให้กับสิ่งที่มีชื่ออยู่แล้ว คือการสร้างของสองอย่างที่เป็นอันเดียวกัน** ในหัวของคนใช้

**ชื่อหน้า** (จาก `NAV_ITEMS` ใน `AdminApp.tsx` ซึ่งเป็นรายการเดียวของแอป):
แผงควบคุม · ขอใบเสนอราคา · ประวัติใบเสนอราคา · จัดการโปรโมชันส่วนลด · จัดการข้อมูลพนักงาน ·
จัดการผู้ใช้งานระบบ · บัญชีห้ามเสนอราคา · และกลุ่มบันทึกและรายงาน (บันทึกการเรียก API ·
บันทึกการแก้ไข · บันทึกระบบ · traffic)

**หัวข้อย่อยของหน้าตั้งค่า** (`SETTINGS_SUBITEMS`): เงื่อนไขหลัก · สินค้าพ่วงเสริม ·
ระงับเมื่อหมดสต็อก · ขั้นต่ำสั่งซื้อ · บล็อกสินค้า · ค่าขนส่ง & เครดิต

**ชื่อแท็บเป็นส่วนหนึ่งของ URL แล้ว** — `admin/navHash.ts` ถือทะเบียน slug กลาง (`TAB_SLUG`)
เพราะ refresh แล้วเด้งกลับ "แผงควบคุม" ทุกครั้งคือบั๊กที่ถูกแจ้งเข้ามาจริง สองกติกาที่ทำให้
hash ของหน้าแม่กับตัวกรองของหน้าลูกอยู่ร่วมกันได้อยู่ในหัวไฟล์นั้น — อ่านก่อนเพิ่มแท็บใหม่
และ **slug มีที่เดียวคือ `TAB_SLUG`** หน้าลูกอ้างค่านั้น ไม่พิมพ์สตริงซ้ำ

## 5. LIFF — สามไฟล์ที่ถือโทเคนชุดเดียวกันคนละสำเนา

`product-search.html` (1,275 บรรทัด) · `quote-edit.html` (4,120) · `register.html` (1,302)
แต่ละไฟล์มี `:root { --green … --border … --radius … }` **ของตัวเอง** ไม่มีไฟล์ CSS กลาง

**เคยขัดกันจริงและไม่มีใครเห็นมาสองปี — แก้แล้ว 2026-09-12:** `--danger-bg` เป็น `#ffe7e7`
ใน `product-search.html` แต่เป็น `#fff0f0` ในอีกสองไฟล์ **และมันต่างกันมาตั้งแต่คอมมิตแรก
(`beff3ad`)** ไม่ใช่การเพี้ยนระหว่างทาง — ซึ่งแย่กว่า เพราะแปลว่าไม่มีจังหวะไหนเลยที่มันเคยตรงกัน
ให้ใครสังเกตเห็น
**ตัวที่แปลกแยกคือตัวที่ตกเกณฑ์ contrast ด้วย** (วัดเอง ไม่ใช่เดา): `--danger` `#d42b2b`
บน `#ffe7e7` ได้ **4.27:1** ซึ่ง **ตก** เกณฑ์ 4.5 ของตัวอักษรขนาดปกติ — และของที่วางบนพื้นนั้น
คือ `.prod-stock-badge.out` (12px/600 = ตัวอักษรปกติ) กับปุ่ม `.btn-remove`
ส่วน `#fff0f0` ได้ **4.54:1** ผ่านพอดี ⇒ ยุบมาที่ `#fff0f0` ทั้งสามไฟล์ ตอนนี้
**ไม่มีโทเคนตัวไหนที่ค่าขัดกันแล้ว** (ที่เหลือต่างแค่ช่องว่างใน `rgba()` ซึ่งเป็นค่าเดียวกัน)
สิ่งที่ยังไม่สมมาตรคือ `quote-edit.html` มีโทเคนเพิ่มอีก 5 ตัวที่อีกสองไฟล์ไม่มี
(`--blue` `--blue-dark` `--success` `--success-hover` `--warning-bg`) — นั่นเป็น "ของเกิน"
ไม่ใช่ "ของขัดกัน" จึงปล่อยไว้ได้

⇒ **แก้สีของ LIFF หนึ่งครั้ง แปลว่าต้องแก้สามที่ และพลาดไปหนึ่งที่จะไม่มีใครเห็นจนกว่าจะเปิด
สองหน้าเทียบกัน** — ตรวจซ้ำได้เร็ว ๆ ด้วยการดึง `:root` ของทั้งสามไฟล์มาเทียบคีย์ต่อคีย์

**กฎวันนี้:** แก้โทเคนตัวไหน **ต้องไล่ให้ครบทั้งสามไฟล์ในคอมมิตเดียวกัน** และเขียนในข้อความ commit
ว่าไล่ครบแล้ว การทำไฟล์ CSS กลางเป็นงานที่ถูกต้องแต่เป็นงานของตัวเอง — ต้องถามเจ้าของก่อน เพราะ
มันแตะทั้งสามหน้าพร้อมกันซึ่งเป็นความเสี่ยงคนละระดับกับการแก้สีหนึ่งค่า

**`@media` มี 1 จุดในทั้งสามไฟล์รวมกัน** (`min-width: 520px` ใน `product-search.html`) และ
`quote-edit.html` ทั้ง 4,120 บรรทัด **ไม่มีเลย** — นี่ไม่ใช่ความผิดพลาด: LIFF เปิดในมือถือเป็นหลัก
และหน้าถูกเขียนมาเป็นคอลัมน์เดียวตั้งแต่ต้น **แต่มันแปลว่าห้ามสมมติว่า "หน้านี้ responsive อยู่แล้ว"**
ของที่กว้างเกินมือถือจะล้นเงียบ ๆ

**`viewport` ไม่เหมือนกันสามไฟล์** — `product-search.html` ใส่ `maximum-scale=1.0,
user-scalable=no` ส่วนอีกสองไฟล์ไม่ใส่ คนสายตาไม่ดีจึงซูมได้สองหน้าและไม่ได้หนึ่งหน้า
เป็นเรื่องที่เจ้าของต้องเลือกว่าจะเอาแบบไหนทั้งชุด ไม่ใช่เรื่องที่แก้เงียบ ๆ ทีละไฟล์

**สองกฎเหล็กของ LIFF ที่มาจากบั๊กจริง**

- **`quote-edit.html`: DOM ไม่ใช่ source of truth** — ห้ามอ่านบริษัท/ผู้ติดต่อจาก DOM
  ต้องใช้ `getSelectedCustomer()` เพราะ `render()` รีเซ็ต dropdown แล้วเติมค่าแบบ async
  อ่านจาก DOM จะได้ค่าว่างหรือค่าเก่าโดยไม่มี error
- **สต็อกบนหน้า LIFF เป็น badge เตือนเท่านั้น ห้ามบล็อก** — client ไม่รู้ว่าสินค้าไหนติดกฎระงับ
  เคยใส่ guard `newQty > stock` แล้วบล็อกสินค้าที่ไม่มีกฎไปด้วยทั้งหมด (ถอดออกใน `e141cea`)
  server เป็นด่านจริงเสมอ

**`sendMessages` ของ LIFF ใช้บน LINE PC ไม่ได้ถาวร** — LINE บน PC เปิด LIFF ในเบราว์เซอร์นอก
จึงต้องมีโมดัลคัดลอกเป็นทางสำรองเสมอ ไม่ใช่ทางเลือกเสริม

## 6. LINE Flex — ข้อจำกัดคือดีไซน์

- **`type` ต้องเป็น literal** — `const msg: FlexMessage = { type: 'flex', … }` หรือ
  `type: 'flex' as const` ไม่งั้น TS มองเป็น `string` แล้ว type error
- **ไม่มีตัวแปร CSS ไม่มีธีม ไม่มี media query** ทุกอย่างเป็นค่าคงที่ในไฟล์
- **ข้อความที่เซลล์เห็นคือสิ่งที่หน้า Admin เอาไปแสดงตัวอย่างด้วย** (`BlockRules.tsx:657`
  แสดงประโยค `❌ ระงับการเสนอราคา …` ที่ Flex จะส่งจริง) — แก้ถ้อยคำที่ `flexTemplates.ts`
  แล้วต้องไล่ดูว่าหน้า Admin ที่ยกมาโชว์ยังตรงอยู่ไหม
- **`npm run diag:line-parity` เป็นด่านของพื้นผิวนี้** — มันเทียบ prompt และรูปร่าง Flex กับ
  golden file ทีละตัวอักษร

## 7. PDF — ความกว้างที่ไม่มีใครหุบได้

- **A4 ตายตัว** (`format: "A4"` ใน `pdfGenerator.ts`) ไม่มี responsive ไม่มีธีม
- **เกือบไม่มีสี** — ทั้งไฟล์มี hex 2 ค่า (`#ef4444`, `#000000`) เอกสารที่ลูกค้าได้รับจึงอ่านได้
  เท่ากันทั้งบนจอและบนกระดาษขาวดำ **อย่าเพิ่มสีเข้าไปโดยไม่ถาม** — ใบเสนอราคาถูกพิมพ์จริง
- **ฟอนต์ Sarabun โหลดจาก Google Fonts** ⇒ ต้องมีเน็ต และในกล่อง Docker มี `fonts-thai-tlwg`
  เป็น fallback ไว้แล้ว เปลี่ยนฟอนต์เมื่อไหร่ต้องคิดถึงทั้งสองทาง
- **ลายเซ็นต้องชื่อ `{salesperson_id}.png`** ใน `data/sale_sigs/` — ชื่อไฟล์คือสัญญา ไม่ใช่ธรรมเนียม
- Chromium ในคอนเทนเนอร์ต้องมี `init: true` ใน `docker-compose.yml` ไม่งั้น zombie process สะสม

## 8. กฎที่ข้ามทุกพื้นผิว

- **ห้ามสื่อความหมายด้วยสีอย่างเดียว** — ทุกที่ที่ใช้สีต้องมีข้อความหรือไอคอนกำกับ
  (กฎนี้เขียนไว้เองแล้วใน `admin/logs/format.ts`) คนตาบอดสีและกระดาษขาวดำเห็นเหมือนกันคือ "ไม่เห็น"
- **เวลาปัก `Asia/Bangkok` เสมอ ห้ามใช้ TimeZone ของเบราว์เซอร์** — ต้องตรงกับตัวกรองวันที่ฝั่ง SQL
  ที่ตีความเป็นวันตามเวลาไทย ไม่งั้นเครื่องที่ตั้งโซนอื่นเห็นวันในตารางไม่ตรงกับช่วงที่กรอง
  · เวลาสัมพัทธ์ใช้ได้ แต่ **เวลาเต็มต้องอยู่ใน tooltip ของทุกจุดที่ใช้ค่านั้น**
- **สามสถานะ ไม่ใช่สถานะเดียว** — ว่าง / กำลังโหลด / พัง ต้องออกแบบครบทั้งสาม
  พื้นที่ว่างเปล่าที่ไม่บอกว่าทำไมถึงว่าง คนอ่านว่า "พัง" (`EmptyState` และ `SkeletonRows`
  มีอยู่แล้วใน `logs/ui.tsx`)
- **ปุ่มที่มีแต่ไอคอนต้องมี `aria-label` ที่เป็นประโยคจริง** (มี 17 ไฟล์ที่ทำแล้ว)
- **สิทธิ์บนหน้าจอเป็นแค่การซ่อน UI** — `roles` ใน `NAV_ITEMS` ซ่อนเมนู ตัวบังคับจริงคือ
  `requireRole` ฝั่ง backend เสมอ ห้ามถือว่าการซ่อนปุ่มคือการป้องกัน

## 9. รายการห้าม

- **ห้ามเขียน hex ลง `.tsx` / `.ts` ของ admin** — สีอยู่ใน `index.css` ที่เดียว (ตอนนี้ 0 จุด)
- **ห้ามใช้อีโมจิเป็นไอคอนใน Admin** — ใช้ `lucide-react` (อีโมจิบน LIFF/Flex/ข้อความ LINE
  เป็นคนละเรื่องและถูกต้องที่นั่น)
- **ห้ามเพิ่มเบรกพอยต์ใหม่** — ใช้ค่าดีฟอลต์ของ Tailwind ที่มีอยู่
- **ห้ามแก้โทเคนของ LIFF ไฟล์เดียว** — สามไฟล์ในคอมมิตเดียวกัน
- **ห้ามเอา React/Vite/build step เข้า `liff_pages/`**
- **ห้ามแก้ไฟล์ใน `public/`** — นั่นคือ build output ของ `frontend/`
- **ห้ามอ่านค่าที่ผู้ใช้เลือกจาก DOM ใน `quote-edit.html`** — ใช้ state
- **ห้ามให้ client บล็อกจากสต็อกดิบ**
- **ห้ามปล่อยพื้นที่ว่างเปล่าโดยไม่บอกเหตุผล**
- **ห้ามแตะไฟล์ UI ก่อนเจ้าของตอบโอเค** (`AGENTS.md` ข้อ 7)

## 10. เช็กลิสต์ก่อนบอกว่าจอเสร็จ

**ความกว้างที่ต้องเปิดดูจริง** — และต้องดูในรอบเดียวกัน ไม่ใช่คนละวัน

```
390     มือถือจริง  ← LIFF ทุกหน้าต้องผ่านความกว้างนี้
640     เส้น sm ของ admin (ฝั่งแคบ)
641     เส้น sm ของ admin (ฝั่งกว้าง) — ต้องไม่มีอะไรค้างจากฝั่งซ้าย
1280    จอทำงานจริงของแอดมิน
A4      ถ้างานนี้แตะ PDF — เปิดไฟล์ที่ออกมาดู ไม่ใช่ดูแค่ HTML
```

**รายการที่ต้องตอบได้ทุกข้อ**

- [ ] จอนี้อยู่พื้นผิวไหน และใช้กติกาของพื้นผิวนั้น ไม่ใช่ของพื้นผิวที่เพิ่งทำงานมา
- [ ] เจ้าของเห็น mockup และตอบโอเคแล้ว
- [ ] ของใหม่ใน admin ประกอบจากคอมโพเนนต์ที่มีอยู่ (หัวข้อ 3) ไม่ได้ก๊อปบล็อกจากหน้าอื่นมาแก้
- [ ] ไม่มี hex ใหม่ใน `.tsx` · **เปิดดูทั้งธีมมืดและธีมสว่าง** (กดปุ่มสลับจริง)
- [ ] ดูครบทั้งสามสถานะ: ว่าง / กำลังโหลด / พัง
- [ ] คำบนจอตรงกับหัวข้อ 4 · ปุ่มไอคอนมี `aria-label`
- [ ] ไม่มีที่ไหนสื่อความหมายด้วยสีอย่างเดียว
- [ ] แตะ LIFF → ไล่ครบทั้งสามไฟล์ที่เกี่ยวข้อง และเปิดบนมือถือจริง (ไม่ใช่แค่ย่อหน้าต่าง)
- [ ] แตะ Flex → `npm run diag:line-parity` ผ่าน · แตะ PDF → `npm run diag:pdf-render` ผ่าน
- [ ] `npm --prefix frontend run lint` และ `run build` ผ่าน **และเปิดดูด้วยตา** —
      build ผ่านไม่ได้แปลว่าหน้าไม่ขาว
- [ ] ถ้ารอบนี้ทำให้ประโยคในไฟล์นี้ไม่จริง แก้ไฟล์นี้ในคอมมิตเดียวกัน
