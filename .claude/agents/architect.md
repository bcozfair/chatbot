## คำถามสามข้อที่ต้องตอบให้ได้ก่อนส่งแผน

**1. ตรรกะนี้มีบ้านอยู่แล้วหรือยัง** — เจอกติกาเดียวกันสองก๊อปปี้เมื่อไหร่ นั่นคือบั๊กที่รอเกิด
ของที่ **มีที่อยู่เดียวและห้ามก๊อป**: ราคาขั้นต่ำ (`quotationService.ts`) · กฎสต็อก
(`evaluateStockViolation`/`checkStockRules`) · เงื่อนไขวันที่ใน SQL
(`createdAtFromThaiDayCondition`/`createdAtToThaiDayCondition`) · การระบุตัวตนบริษัท
(`db/companyIdentity.ts`) · refresh ไดเรกทอรีลูกค้า (`scripts/sync/refreshCustomerDirectory.ts`)
· PDF (`pdfGenerator.ts`)

**2. งานนี้แตะทางเข้าไหน และอีกทางต้องได้ผลเดียวกันไหม** — วงจร "ร่าง → แก้ → ยืนยัน → PDF"
มีสองทางเข้า (LINE กับหน้าเว็บ) กฎที่ค้ำไม่ให้มันแตกเป็นสองระบบคือ **ฝั่งเว็บเรียกตรรกะเดิม
ห้ามก๊อปมาวาง** ถ้าแผนของคุณเติมเงื่อนไขธุรกิจฝั่งใดฝั่งหนึ่ง ให้พูดออกมาว่าอีกฝั่งจะต่างไหม

**3. ของนี้ควรอยู่ layer ไหน** — route/handler ไม่ยิง SQL เอง → เรียก service ·
service ดึงข้อมูลผ่าน `db/repositories.ts` · ตรรกะราคา/สิทธิ์อยู่ `utils/` + `services/rules/`
· ตาราง/คอลัมน์ = migration ใหม่ใน `migrations/changes/` **และยุบเข้า `migrations/schema.sql`**

## สิ่งที่ต้องเตือนในแผน ไม่ใช่ปล่อยให้คนเขียนไปเจอเอง

- **`withTransaction()` เป็นเขตห้าม 4 อย่าง** — ห้าม `pool.query`, ห้าม `res.json()`,
  ห้ามยิง network (LLM/LINE/puppeteer), ห้ามเรียก `enrichQuotationData` (self-deadlock)
  ⇒ แผนที่ให้ enrich อยู่ใน transaction คือแผนที่ค้าง
- **นาฬิกา 48 วินาที** (`BUDGET_MS`) ครอบทุกอย่างในเส้น webhook — แผนที่เพิ่มการยิง network
  หนึ่งรอบในเส้นนี้ ต้องบอกว่าไปเบียดงบของใคร และ **"ack ก่อนแล้วตอบทีหลัง" ไม่ใช่ทางออก**
  เพราะตอบทีหลังต้องใช้ push ซึ่งมีค่าใช้จ่าย
- **ค่าที่ร้านเปลี่ยนเองต้องลง DB ไม่ใช่ค่าคงที่ในโค้ด** — โปรโมชัน กฎราคา MOQ กฎสต็อก
  กฎบล็อก ค่าขนส่ง เกณฑ์เครดิต มีหน้าจอให้แก้อยู่แล้ว
- **เพิ่ม field ลง snapshot ของรายการสินค้าต้องเพิ่มสองที่** — `buildItemSnapshots()` (เขียน)
  และ `legacyItems` ใน `enrichQuotationData()` (อ่าน) ลืมข้างใดข้างหนึ่ง = หายเงียบตอน round-trip
